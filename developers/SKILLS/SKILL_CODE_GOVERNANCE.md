# SKILL_CODE_GOVERNANCE

## 适用场景

- 新功能开发
- Bug 修复
- 重构与配置行为调整

## 输入

- 任务目标与验收标准
- 受影响文件路径或模块范围
- 相关规范文档：`developers/CODE-STYLE.md` 与对应语言规范

## 前置检查

1. 确认任务边界，避免顺手修复无关问题。
2. 确认是否涉及对外接口变更；若涉及，必须提供兼容路径或迁移说明。
3. 确认已有本地改动与当前任务是否冲突。

## 执行步骤

1. 读取 `developers/CODE-STYLE.md` 与对应语言规范。
2. 明确改动边界：仅修改与当前任务直接相关的文件。
3. 编码时遵守兼容优先原则，避免无迁移路径的破坏性变更。
4. 检查导出函数、共享常量、关键数据结构是否需要补充注释/JSDoc。
5. 运行最小必要验证（测试、构建或静态检查），记录结果。

## 输出

- 代码改动清单（文件路径 + 变更目的）
- 验证记录（执行命令、通过/失败结果、失败原因）
- 若存在兼容影响，补充迁移说明或风险提示

## 失败处理

- 测试或构建失败：记录最小复现步骤与错误摘要，标记为阻断项，不得伪造通过。
- 规范冲突无法当场解决：优先保持现有稳定行为，并在输出中标记待决策点。
- 发现无关脏改动：不回滚非本任务改动，只在输出中声明影响。

## 示例

- 输入："修复 agent 配置解析在空 tools 时崩溃"
- 执行：限定 `packages/pi-workflow/src/agents` 与相关测试；补充空值保护；运行对应测试。
- 输出：列出修改文件、测试命令、结果与兼容性结论。

## 完成标准

- 代码风格与注释约束满足规范。
- 改动范围清晰且可解释。
- 验证结果可复现。
