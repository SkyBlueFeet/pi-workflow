# SKILL_CODE_QUALITY_CHECK

## 适用场景

- 功能完成后的质量核验
- 提交前自检
- 阶段性质量巡检

## 输入

- 待检查改动范围（文件、模块、功能）
- 目标质量门槛（测试、构建、规范、报告要求）
- 相关上下文（计划阶段、风险点、已知限制）

## 前置检查

1. 确定本次检查是"任务收尾自检"还是"阶段巡检"。
2. 确定最小可执行验证命令集。
3. 确定输出形式（终端结论或报告文件）。

## 检查清单

1. 正确性：核心路径是否通过测试或最小复现实验。
2. 兼容性：是否引入破坏性变更，是否有迁移说明。
3. 可维护性：命名、结构、注释与边界说明是否充分。
4. 安全性：输入校验、错误处理、敏感信息处理是否合理。
5. 文档性：必要文档与计划状态是否同步。

## 输出要求

- 对每个检查项给出通过/不通过结论。
- 对不通过项给出阻断级别与修复建议。
- 需要沉淀报告时，遵循 `developers/REPORTS/README.md`。
- 若无法执行某项检查，必须说明原因、影响面与替代方案。

## 失败处理

- 测试环境不可用：标记为"未验证"并提供本地可执行命令。
- 结果与预期冲突：保留原始现象，避免提前下结论。
- 阻断项过多：按优先级排序，先修复高风险问题。

## 示例

- 输入："对本次 config 模块改动做提交前质量检查"
- 执行：跑相关测试与静态检查，逐项给出通过/不通过，列出阻断项。
- 输出：终端摘要 + 必要时生成质量报告。

## 完成标准

- 核心检查项均有明确结论。
- 阻断项已标注并附修复建议。
- 输出可支撑后续提交或验收决策。
