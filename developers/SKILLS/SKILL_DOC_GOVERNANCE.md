# SKILL_DOC_GOVERNANCE

## 适用场景

- developers 文档新增或更新
- 计划、分析、报告类文档维护

## 输入

- 文档目标（新增、修订、归档）
- 目标文档路径与受影响引用
- 相关规范文档：`developers/DOC-RULES.md`

## 前置检查

1. 确认文档类型（计划、分析、报告、规范）并匹配对应模板。
2. 确认是否要求版本锚点。
3. 确认是否需要同步索引入口。

## 执行步骤

1. 读取 `developers/DOC-RULES.md`，确认命名与结构约束。
2. 按目标文档类型选择模板或既有结构，保持章节口径一致。
3. 如文档要求版本锚点，补齐创建时间、更新时间与快照信息。
4. 增量更新时记录变更理由与影响范围，避免只改结论不改依据。
5. 检查索引文档是否需要同步更新链接。

## 输出

- 文档变更清单（新增/修改/删除）
- 版本锚点与引用更新结果
- 若存在未完成项，列出待补充内容

## 失败处理

- 链接无法确认：标记为待校验项并保留明确占位，不写伪链接。
- 模板缺失：沿用同类既有文档结构并在输出中说明依据。
- 事实依据不足：保留问题列表，不臆造结论。

## 示例

- 输入："更新阶段计划文档并补验收结论"
- 执行：按计划模板补齐 DoD、更新时间、证据链接，并同步 `developers/INDEX.md` 入口。
- 输出：给出更新文件列表与新增结论摘要。

## 完成标准

- 文档结构、命名、版本信息符合规范。
- 变更可追溯，链接可达。
- 与相关索引/入口文档保持一致。
