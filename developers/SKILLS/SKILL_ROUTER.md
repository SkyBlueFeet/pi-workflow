# SKILL_ROUTER

> 统一任务入口。执行任务前先在本文件定位任务类型，并按"完成后必做"收尾。

---

## 路由表

| 任务类型 | 执行前读取最小集 | 执行中约束 | 完成后必做 |
|---|---|---|---|
| 功能实现 / 问题修复 | [../CODE-STYLE.md](../CODE-STYLE.md) + 对应语言规范 + [SKILL_CODE_GOVERNANCE.md](./SKILL_CODE_GOVERNANCE.md) | 保持兼容优先；遵守注释与导出约束；仅改动任务相关文件 | 运行质量检查 -> 更新会话留痕 -> 必要时更新计划状态 |
| 文档新建 / 修改 | [../DOC-RULES.md](../DOC-RULES.md) + [SKILL_DOC_GOVERNANCE.md](./SKILL_DOC_GOVERNANCE.md) | 保持版本锚点与命名规范；结构与语气一致 | 执行文档合规自检 -> 更新会话留痕 |
| 计划创建 / 调整 / 完成 | [../PLANS/TEMPLATE.md](../PLANS/TEMPLATE.md) + [SKILL_PLAN_INDEX.md](./SKILL_PLAN_INDEX.md) | 计划状态、DoD 与验收口径一致 | 同步索引与入口引用 -> 更新会话留痕 |
| 代码质量巡检 | [SKILL_CODE_QUALITY_CHECK.md](./SKILL_CODE_QUALITY_CHECK.md) + [../REPORTS/README.md](../REPORTS/README.md) | 检查结论可复现；问题分级明确 | 输出报告或检查结论 -> 标注阻断项与建议 |

---

## 执行规则

- 无明确分类时，默认按"功能实现 / 问题修复"路由。
- "完成后必做"属于任务定义的一部分，不视为可选步骤。
- 若任务同时包含代码与文档改动，按两条路由分别执行收尾动作。

## 输出约定

- 每次任务结束至少输出三项：改动清单、验证结果、后续动作。
- 若存在阻断项，必须单独列出"阻断原因 + 影响范围 + 建议处理"。
- 若未执行某项必做动作，必须说明未执行原因与补救计划。

## 失败升级路径

1. 先在对应 Skill 的"失败处理"章节按标准兜底。
2. 若仍无法关闭风险，回到本路由标记为阻断任务。
3. 将阻断结论同步到任务上下文与计划文档，避免状态失真。
